# تنظیمات — یعنی چه، چرا این مقدار، و چطور عوضش کنم

سه مشکل قدیمی که این سند جوابشان است:

1. **پیش‌فرض‌ها را نمی‌شد دید.** حالا `bot config` همه را گروه‌بندی‌شده چاپ می‌کند و
   کنار هر مقدار می‌گوید **از کجا آمده**: پیش‌فرضِ خودِ ابزار، یا `config.json` تو،
   یا مقداری که با پیش‌فرض فرق دارد و دارد پیش‌فرض را ساکت کنار می‌زند.
2. **عوض‌کردن یک کلید یعنی ویرایش دستی JSON.** حالا `--set` با نوع‌سنجی.
3. **ست کردن یک مقدار، برای همیشه می‌چسبد.** `--unset` کلید را برمی‌دارد تا پیش‌فرض
   جدیدِ نسخهٔ بعدی دوباره کار کند. این مهم است: `config.json` تو `protocols` را قفل
   کرده بود و wireguard را از نسخهٔ ۱.۶.۴ به بعد بی‌صدا حذف می‌کرد.

```bash
bot config                                  # همه‌چیز، گروه‌بندی‌شده، با منبع هر مقدار
bot config --get targets                    # فقط یک مقدار (اسکریپت‌پسند)
bot config --set best_n=20                  # یک کلید، با نوع درست
bot config --set "targets=https://www.gstatic.com/generate_204, https://api.telegram.org/"
bot config --unset targets                  # برگشت به پیش‌فرض خودِ ابزار
bot config --doctor                         # فقط چیزهایی که غلط یا کهنه‌اند
```

`*` کنار هر کلید در جدول یعنی «این مقدار از پیش‌فرض فرق دارد». اگر `--set` را با
`-c` به فایل دیگری بدهی، همان فایل نوشته می‌شود، نه `config.json`.

## جدول کامل — از خودِ ابزار بپرس

جدول ۴۰ ردیفی اینجا نگه داشته نمی‌شود: با هر نسخه کهنه می‌شد. منبعِ حقیقت خودِ
`DEFAULTS` است و `bot config` آن را چاپ می‌کند:

```bash
bot config                  # همهٔ کلیدها، گروه‌بندی‌شده، با مقدار و منبع هر کدام
bot config --get targets
bot config --doctor         # فقط چیزهایی که غلط یا کهنه‌اند
```

`*` کنار هر کلید یعنی «این مقدار از پیش‌فرض فرق دارد».

## چهار کلیدی که واقعاً سرنوشت را عوض می‌کنند

### ۱) `targets` — «خوب» یعنی چه
پیش‌فرض سه تارگت است، و عمداً سه نوع مختلف:

| تارگت | چه چیزی را ثابت می‌کند |
|---|---|
| `https://www.gstatic.com/generate_204` | ارزان‌ترین آزمون: تونل زنده است |
| `https://en.wikipedia.org/wiki/Main_Page` | یک **صفحهٔ واقعی** با هدر و بدنه — «۲۰۴ جواب داد» با «مرورگر کار می‌کند» یکی نیست |
| `https://api.telegram.org/` | میزبی که روی خط ایران **واقعاً بسته است** (۱۵ نوامبر: `tcp=closed` مستقیم) |

یوتیوب و توییتر عمداً در لیست نیستند: روی خط تو با SNI بسته‌اند، پس نودی که
«ردشان می‌کند» ممکن است سالم باشد و ما بی‌دلیل دورش بیندازیم.

### ۲) حالت پیش‌فرض = «زنده و قابل استفاده»، نه «یک URL را باز کرد»
قبلاً دو حالت بد داشتیم: با تارگت، نودی که ترافیک حمل می‌کرد ولی آن یک URL را
باز نمی‌کرد دور انداخته می‌شد (نتیجه: `best` خالی، در حالی که ۸ نود زنده بودند)؛
بدون تارگت، هیچ‌چیز ثابت نمی‌کرد نود بیشتر از یک ۲۰۴ حمل می‌کند.

حالا یک قانون، در `gozar/core_live.py`، و **همه‌جا همان** (فایل‌ها، شمارش‌ها،
نمایش، تست‌ها):

```
زنده و قابل استفاده  =  صفحهٔ واقعی باز شد  +  exit IP جور دیگری بود  +  از سقف سرعتِ خودت رد نشد
```

و بعد:
- `best`/`bak` = مجموعهٔ زنده، **تارگت‌اوکی‌ها همیشه جلوتر** (حتی اگر کندتر باشند)
- `data/ok.txt` = فقط آن‌هایی که **همهٔ** تارگت‌ها را پاس کردند (زیرمجموعهٔ سخت‌گیرانه)
- `--strict-target` = رفتار قدیمی، اگر خواستی

نکتهٔ صادقانه: سرعت فقط **ترتیب** می‌دهد، هرگز حکم نمی‌دهد. نود کندترِ پاس‌شده
همیشه بالاتر از نود تندترِ پاس‌نشده می‌نشیند.

### ۳) `max_per_subnet` — یک سرور با پنج در، پنج نود نیست
در گزارش ۱۵ نوامبر، **۵ نود از ۸ نود** روی `82.38.31.180–203:8080` بودند: یک ماشین
با پنج پورت. `max_per_endpoint` فقط `IP:port` را می‌شمارد، پس این‌ها را قبول می‌کرد.
حالا سقف `/24` هم هست (پیش‌فرض ۶؛ `0` = خاموش، `--max-per-subnet N` برای هر اجرا).

### ۴) `min_kbps` — سرعت به‌عنوان کف، نه به‌عنوان معیار
صفر = خاموش. اگر بگذاری، نودی که واقعاً صفحه می‌آورد ولی ۳KB/s است از best/bak
بیرون می‌ماند. این تنها جایی است که سرعت می‌تواند «حکم» بدهد، و حکمش هم
«نمی‌تواند یک صفحه را حمل کند» است، نه «کند است».

## `--doctor` چه چیزهایی را علامت می‌زند

- `targets` خالی (حالت فقط‌زنده‌بودن)
- تارگتی که روی خط ایران با SNI بسته است (یوتیوب/توییتر/اینستاگرام)
- `protocols` قفل‌شده در `config.json` که wireguard را حذف کرده
- `min_kbps` ست‌شده ولی `page_probe_urls` خالی (کف سرعت هرگز اندازه‌گیری نمی‌شود)
- `strict_exit_proof` روشن با `verify_exit_ip` خاموش (ترکیبی که کد مرده است)
- `tier_max` کوچک (کمتر از ۳۰۰ یعنی بخش بزرگی از استخر دیده نمی‌شود)

## v1.6.8 — دو کلیدی که معنی «لیست» را تعیین می‌کنند

| کلید | پیش‌فرض | یعنی چه |
|---|---|---|
| `list_mode` | `target` | `best`/`bak` فقط نودهایی که **همهٔ** تارگت‌ها را پاس کردند. `live` = همهٔ زنده‌ها (رفتار ۱.۶.۷) |
| `list_fallback` | `false` | اگر **هیچ** نودی پاس نکرد، لیست خالی می‌ماند و ابزار دلیلش را می‌گوید. `true` = لیست از استخر زنده پر شود (نااثبات‌شده) |

نودی که یک تارگت را رد کرد **نمی‌میرد**؛ در `gen.txt` می‌ماند و `--from gen` وصلش
می‌کند. این همان قانونی است که خواستی: «در لیست نباشد، در زنده‌ها بماند».

```bash
bot --reset discover -n 20        # استخر خالی، state قبلی آرشیو می‌شود
bot discover --list-mode live      # همهٔ زنده‌ها در لیست، تارگت‌اوکی اول
bot connect --from gen             # وصل‌شدن به استخر زنده
```
