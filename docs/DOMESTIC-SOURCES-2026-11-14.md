# منابع داخلی و نت ملی — چه چیزی هست، چه چیزی نیست، چطور تست کنیم

**تاریخ:** ۲۰۲۶-۱۱-۱۴ · **نسخه:** v1.7.0
**پرسش:** آیا منبعی هست که «تست‌ها را در نت ملی» ممکن کند — مثلاً لینک‌های ایتا/روبیکا؟
**تصمیم شما:** منابع ایرانی فقط **پیدا** شوند، به کد **اضافه نشوند**. با فلگ خودتان اضافه می‌کنید.

---

## ۱) جواب کوتاه

| پرسش | جواب |
|---|---|
| کانفیگ v2ray روی ایتا/روبیکا منتشر می‌شود؟ | **بله**، زیاد — ولی به‌صورت **پست متنی و کانال**، نه لینک ساب پایدار |
| می‌شود اینها را خودکار کشید و تست کرد؟ | با اسکرپر کانال (نمونه‌ها پایین) — ولی مسیر تست داخل ایران شما باید اجرا شود، اینجا فقط داده‌اش را می‌شود کشید |
| آیا github به هاست‌های ایتا/روبیکا از این سندباکس دسترسی دارد؟ | **نه**: DNSresolve می‌شود (`eitaa.com`→`2.189.58.6`، `rubika.ir`→`5.106.8.151`) ولی هیچ پاسخی نمی‌آید (HTTP 000، تایم‌اوت). این سندباکس در ایران نیست |
| منبع ایرانی آماده‌ی commit در ۴۳ سورس باشد؟ (Arvan/Parspack/آروان/S3 داخلی) | پیدا نشد؛ ترافیک داخلی‌‌محور است، نه v2ray-out |
| چه چیزی *واقعاً* به کار می‌آید | ۱) لینک‌های پایدار داخل ایران (چند تا، جدول ۳) ۲) هدف‌های تست داخلی (جدول ۴) بدون تغییر کد |

## ۲) واقعیت دربارهٔ ایتا و روبیکا

هر سه پیام‌رسان ایرانی (ایتا، روبیکا، بله) v2ray را **عبور می‌دهند**؛ هیچ‌کدام فیلترشکن به کاربر نمی‌دهند.
چیزی که در جست‌وجو پیدا شد:

- کانال‌های تلگرامی که *همان* کانفیگ‌ها را منتشر می‌کنند و روی ایتا/روبیکا **آینه** (mirror) دارند؛ شمارندهٔ نصب و کلاینت‌ها همه‌جا از `eitaa.com/<channel>` استفاده می‌کنند، لینک ساب پایدار از `eitaa.com` دیده نشد.
- `github.com/BaseMax/eitaa-extractor` و `moshafieeha/Eitaa-Messenger-Crawler` و `BaseMax/eitaa-forwarder` — اسکرپرهای آماده برای استخراج پست‌های کانال ایتا (`eitaa.com/<channel>` HTML).
- هاست‌های داخلی که واقعاً لینک ساب **پایدار** می‌دهند، با فرمت `https://...ir/xxx.txt` یا ورکر/ساب‌فیلتر هستند، نه ایتا/روبیکا.

**نتیجه:** کانفیگ‌ها در ایتا/روبیکا **متن‌اند، نه لینک ساب**؛ پس این‌ها «منبع» به معنی URL قابل fetch نیستند. اگر خودتان ردیف کلید `vless://` / `vmess://` را از کانال کپی کرده‌اید، همان کاری که باید، در جدول ۵ آمده — و این همان مسیر پیشنهادی خالق کد (`custom_configs` / `import_files`) است.

هیچکدام تأیید نشد (از این سندباکس دسترسی نیست) و **هیچ‌کدام در کد نیامده‌اند**:

| لینک | چه می‌گوید | ریسک |
|---|---|---|
| `https://serverv.net/mci-test.json` | مخصوص همراه اول توسط سازنده‌اش ادعا شده | سرور شخصی، regexp نشد، فقط ادعا |
| `https://serverv.net/KevinVPN.json` | ساب پروتکل sing-box | همان |

## ۴) هدف‌های تست داخلی (این‌ها را می‌شود همین حالا با `-t` داد، بدون تغییر کد)

برای اینکه «نت ملی» را بسنجیم، هدف باید سرویسی باشد که در قطعی بین‌المللی **زنده می‌ماند**:

| هدف | چرا | نکته |
|---|---|---|
| `http://eitaa.com/` / `http://rubika.ir/` | پیام‌رسان‌های ملی، داخل کشور توزیع می‌شوند | از این سندباکس **تایم‌اوت** می‌دهند (ایران نیست)؛ از خط شما لود می‌شوند |
| `https://www.aparat.com/` | CDN داخلی (آروان/دراک) | سبک است و بدون JS دیوار ندارد |
| `https://divar.ir/` / `https://www.digikala.com/` | داخلی، پرترافیک | quick تحویل صفحه بدون دیوار |
| `https://shaparak.ir/` یا بانک‌ها | زیرساخت پرداخت | در قطعی کامل بیرونی معمولاً خاموش‌گذاری نمی‌شود — اما احتمال reset |
| `generate_204` (پیش‌فرض) | canary | برای «زنده بودن» کافی است، نه «نت ملی» |

فرمول تست در نت ملی:
```bash
# منابع را از فایل داخل ایران بخوان و روی هدف داخلی بسنج
gozar -o data-nm discover -i /path/in-iran/configs.txt \
  -t 'https://www.aparat.com/' --no-probe -p vless,trojan,vmess,ss,hysteria2
```
اگر می‌خواهید *فقط* منبع داخلی استفاده شود: `--domestic` را با `domestic_sources` تنظیم‌شده بدهید (فقط وقتی که خودتان URL را در config اضافه کرده باشید).

## ۵) اگر خودتان می‌خواهید منابع ایرانی اضافه کنید (سه مسیر، به ترتیب سادگی)

**الف) یک فایل (بدون تغییر کد، پیشنهادی برای ایتا/روبیکا):**
1. ردیف‌های `vless://`، `vmess://`، `trojan://`، `ss://`، `hysteria2://` را از پست کانال کپی کنید در `~/iran-subs/mci.txt`.
2. (اختیاری) با دکمهٔ ساب‌ها به base64 هم کار می‌کند — `_extract_links` خودش دیکود می‌کند.
3. اجرا:
```bash
gozar discover -i ~/iran-subs/mci.txt -t 'https://www.aparat.com/'
```

**ب) یک URL داخلی، دائمی (بدون تغییر کد):**
```bash
gozar config --set domestic_sources https://your.iran.sub/list.txt
gozar discover --domestic       # فقط منبع داخلی
```
این همان فلگی است که گفته بودید باید باشد: **کد تغییر نمی‌کند**، شما URL را می‌دهید.

**ج) برای اینکه داخل ۴۳ سورس دائمی بیاید (تغییر کد، فقط با دستور خودتان):**
```python
# gozar/core_sources.py → MEDIUM_SOURCES
"https://your.iran.sub/list.txt",     # measured: ...
```
یا:
```bash
gozar config --set custom_configs '["vless://...","vmess://..."]'
```

## ۶) چیزی که پیشنهاد *نمی‌کنم*

- **کشیدن خودکار کانال ایتا/روبیکا** با اسکرپر: نتیجهٔ آن `vless://` خام در متن فارسی است، نه ساب؛ نرخ آپدیت پایین، خطای کپی زیاد، و از خارج ایران اصلاً پاسخ نمی‌دهد — این همان چیزی است که در نرخ «تست‌شده/پارس‌شده» شلاق می‌خورد و داده را آلوده می‌کند.
- **قرار دادن `eitaa.com`/`rubika.ir` در `baseline_hosts`**: اندازه‌گیری پینگ شما را به سرویسی وابسته می‌کند که از خارج ایران کند/مسدود است.
- **تصمیم دربارهٔ سورس‌های داخلی از داده‌های این سندباکس**: ما اینترنت ایران را نمی‌بینیم. هر چیزی که اینجا «سالم» چاپ شود، صرفاً از مسیر بیرونی است.

## ۷) سخن آخر

- سه چیزی که نیاز داشتید امروز **موجود** است: (۱) این سند، (۲) `-i`/`--import` برای فایل داخلی، (۳) `domestic_sources` + `--domestic` برای لینک داخلی. **هیچ منبع ایرانی به کد اضافه نشد**، مطابق دستور شما.
- برای این‌که «منابع ایرانی» را در عدد ببینید، همان `bot sources -t https://www.aparat.com/` که در v1.7.0 تازه ایمن شده، روی خط خودتان اجرا کنید — نه اینجا.
